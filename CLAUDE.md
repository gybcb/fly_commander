## Project

FlyCommander — a keyboard-first, dual-pane file manager for macOS modeled on Total
Commander. Swift + AppKit, macOS 14+. Written in Chinese; comments and UI strings are
Chinese. Personal/local tool (not distributed) — the SFTP path depends on Traversio,
which is AGPL-3.0; distribution obligations do not apply to this repo, but review the
license before shipping a derived version.

## Commands

```
swift build                 # build TCCore + app
swift test                  # all SPM tests (TCCore + app, incl. local-sshd SFTP e2e)
swift run FlyCommander      # run the app

# run a single test (class or method)
swift test --filter PaneTableViewTests
swift test --filter 'PaneTableViewTests/testKeyboardNav'

# UI regression (Tier 2, real AppKit windows)
xcodegen generate
xcodebuild test -scheme FlyCommander -destination 'platform=macOS'
```

The XCUITest scheme is generated by `xcodegen` from `project.yml` into
`FlyCommander.xcodeproj` — regenerate after editing `project.yml`. Two test tiers:
SPM unit tests (fast, run under `swift test`) and XCUITest (real windows; requires
accessibility permission). Note: `xcodebuild ... | tail` swallows the exit code —
read `** TEST SUCCEEDED/FAILED **` in the output, not `$?`.

## Architecture

Single SPM package (`Package.swift`) with two targets plus the Traversio dependency:

- **`TCCore`** — the headless core. Pure Swift + Foundation, **zero AppKit**, fully
  unit-testable. This is where all real logic lives.
- **`FlyCommander`** — a thin AppKit presentation layer over TCCore. Views, windows,
  menus, keyboard capture, and the async/background execution boundary.

The dependency is strictly one-directional: AppKit layer → TCCore. Never import
AppKit into TCCore, and never put IO/blocking in a TCCore path that a test calls.

### The `FileSource` protocol is the central abstraction

`Sources/TCCore/FileSource/FileSource.swift` defines the full filesystem surface
(list, stat, copy/move/rename/mkdir/remove, plus streaming `openReader`/
`streamWrite`). Two implementations:

- `LocalFileSource` — local disk, `sourceID == "local"`, synchronous.
- `SFTPSource` (app layer, wraps Traversio) — `sourceID == "sftp://host:port"`,
  remote.

`sourceID` equality is the **same-source test** the engine uses to pick the fast
path. Any new remote backend (FTP/SMB/WebDAV in the P4 roadmap) should add another
`FileSource` conformance, not special-case it elsewhere.

### The command flow

AppKit events flow one direction and are split across the two layers so the
decision logic stays pure/testable:

1. **`KeyDispatcher`** (app layer, pure) maps `keyCode` + modifiers → `CommandID` +
   `SelectionModel.MoveMode`. F-key keyCodes use the SDK `kVK_*` values (F3=99,
   F4=118, F5=96, F6=97, F7=98, F8=100) — do not guess them.
2. **`CommandRouter`** (TCCore) switches on `CommandID` and mutates the `Workspace`.
   It has no UI — it reports results and requests UI through injected closures
   (`onDelete`, `onView`, `onEdit`, `onSearch`, `onRemoteTransfer`).
3. **`OperationEngine`** (TCCore) performs file ops. Same-source → source's fast
   path (local `FileManager` / SFTP server-side rename). Cross-source → 64 KB
   streaming pump from `openReader` into `streamWrite`.
4. **`FileSource`** impl does the actual IO.

`Workspace` holds the two `FilePane`s + which is active, and pushes state to the UI
via `onActiveChange` / `onOperationState`. `MainViewController` is the single place
that wires these closures; the AppKit layer never reaches into TCCore internals
directly beyond calling its public methods.

### Local vs remote: sync in core, async at the edge

`FilePane.load()` is synchronous (local); `FilePane.loadAsync()` runs `listDirectory`
on a background queue and hops to main, using a monotonically-increasing token to
drop stale results when the user navigates again mid-flight. `setSource` bumps the
token so an in-flight load of the old source can't clobber a new one.

The same split governs transfers: `CommandRouter.handleTransfer` checks whether
either pane's source is remote. If so it hands off to the app-layer **`TransferEngine`**
(which runs the engine in the background, so the main thread/UI never freeze); if
both ends are local it uses the router's synchronous fast path. `TransferEngine`
makes its threading injectable (`runInBackground`, `onMain`) so unit tests substitute
synchronous closures and don't deadlock.

### The command line

A shared bottom `CommandLineBar` (T7). While focus is in a file list, plain printable
characters are captured into the bar instead of moving focus; arrow/F-key events keep
their TC behavior. Parsing is a pure TCCore function (`CommandLineParser`); execution
is `InternalCommandExecutor` (app layer) — internal commands only, no shell
passthrough.

## Environment: reduced AppKit SDK (read before writing AppKit)

This machine's Xcode 26.6 / macOS 26 toolchain ships a **stripped AppKit SDK** where
several documented APIs don't exist or behave differently. Every item below was
reproduced with a probe. Write the workaround directly; do not copy the full AppKit
docs. The complete, probe-verified list (including XCUITest AX gotchas) is in project
memory `reduced-sdk-environment` — consult it before touching AppKit or UI tests.
High-impact build/UI breakers:

- **Never create a `DispatchQueue` dynamically.** Creating a queue after the async
  runtime starts crashes with a generic-metadata SIGSEGV. Use prebuilt system queues
  (`DispatchQueue.global(qos:)`, `.main`). For async→sync bridging (SFTP) use
  `NSLock + Task + DispatchSemaphore` (C API, no generic metadata).
- `NSApplication.ModalResponse` only has `.alertFirst/Second/ThirdButtonReturn`
  (1000/1001/1002); the Nth button (N>3) returns `1000 + (N - 3)` (4th = 1003).
- `NSWorkspace.shared.open(_:withApplication:configuration:)` (single URL + name) is
  gone — use the array form `open([url], withApplicationAt:configuration:)` with
  `urlForApplication(withBundleIdentifier:)` (TextEdit = `com.apple.TextEdit`).
- Programmatic subviews with constraints **must** set
  `translatesAutoresizingMaskIntoConstraints = false`, or the window collapses to
  ~12 pt wide (toolbar buttons vanish, everything "not found" in AX).
- `NSSplitView.setPosition(_:ofDividerAt:)` in `loadView` collapses a pane to 0 —
  defer to `DispatchQueue.main.async` after layout, and implement
  `constrainSplitPosition` to enforce a min width.
- View-based `NSTableView` has no `registerClass:forIdentifier:` —
  `makeView` returns nil; fall back to manually building each `FileCellView`.
- NSView subclasses can't assign `let` stored properties or wire delegates before
  `super.init` — use implicitly-unwrapped `var ...!` and wire after `super.init`.
- F-key / Home / End / PageUp report PUA codepoints (0xE000–0xF8FF) in
  `charactersIgnoringModifiers` — when intercepting "printable" keys for the command
  bar, exclude the PUA range or arrow keys get swallowed.

## Agent Teams 协作规则

When solving complex tasks:

- Decompose the task aggressively into independent subtasks.
- Prefer parallel execution over sequential execution.
- Delegate independent investigation, coding, testing, documentation,
  web research, and validation to teammates.
- Do not perform a task yourself if a teammate can execute it independently.
- Create multiple teammates early rather than waiting for the previous
  teammate to finish.
- Keep the lead agent focused on planning, coordination, integration,
  and final verification.
- When multiple subtasks are independent, start them in parallel.
- Prefer 4-8 concurrent teammates for sufficiently complex tasks.
- Do not create teammates for trivial tasks where delegation adds overhead.
- Avoid unnecessary sequential execution.
- After delegating a task, continue working on other independent tasks
  instead of waiting.
- Keep teammate responsibilities clearly separated to minimize redundant work.
- Prefer independent investigation and execution over agents repeatedly
  asking each other for information.
- Before starting a large task, identify all independent workstreams and
  launch them concurrently.
- Adjust the number of teammates according to available compute resources
  and model throughput.
